What does it look like afterwards?

Feature-based: only 4 workflows for the different logicOpen the interactive view in a new tab

Only one workflow sets the owner

It sets the owner only when it is blank, so it never takes over an existing owner.

What changes lives in a table

Who owns which region and which alert applies are all in one table.

Region is written into the form

The page passes it in when embedding the form; no URL naming guesswork.

To be clear: the wording of the nurture emails cannot be decided by a table, so sending each region its own emails remains a branch inside the workflow.

Why does each of the three workflows query the table?
A HubSpot workflow cannot hand its result to another one. All three read the same table, so they agree and none waits on another. Alerts wait 2 minutes and the owner step 1 minute; whether that is long enough is still unverified.

Appendix: terms
  • Workflow: an automated process in HubSpot, such as setting an owner or sending an email.
  • HubDB lookup table: a table inside HubSpot holding which form, which region, who owns it, and who gets alerted.
  • Hidden field: a form field the visitor cannot see; the page fills it in at load and it is submitted with the form.
  • Re-enroll: whether the same person can enter the same workflow again when they match its conditions a second time.
